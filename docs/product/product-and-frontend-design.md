# TravelPilot 产品功能与前端设计

状态（2026-10-19）：用于记录多用户个人旅行工具的产品边界与前端信息架构。地图默认使用明确标记的 Fake Provider，可配置切换 AMap；天气页面使用 Open-Meteo 当前可提供范围内的预报并显示来源/时间，模拟天气仅用于明确的演示与测试场景。外部 Provider 配额、生产服务连续性和正式商业使用条件尚未验收。好友关系、授权分享、旅行动态与私有记忆建议基础版已实现；生产媒体存储和运营控制仍待补齐，见 [`social-travel-memory-design.md`](social-travel-memory-design.md)。更完整的 Advisor 实现边界见 [`agent-travel-advisor-design.md`](agent-travel-advisor-design.md) 与 [`ROADMAP.md`](../../ROADMAP.md)。

## 1. 产品目标与用户

TravelPilot 帮助个人旅行者把零散旅行灵感整理成地点清单，生成可执行的多日计划，并在旅行变化时看懂并确认计划调整。

- 首发是**邀请码控制的多用户个人工具**，每个账户管理自己的旅行。
- 每个 Trip 只有创建者所有权；默认私有。好友圈阶段已加入显式、可撤销的好友只读分享，不做共同编辑、团队、组织或管理员工作台。
- 用户始终确认地点候选、计划生成和外部事件；系统提供建议，不自动订票、支付或替用户对外联系。
- 计划约束和版本由确定性规划逻辑负责；Agent/模型可以解释偏好、提出目的地/地点/行程建议，但事实需标来源，不能绕过硬约束或在用户确认前写入正式旅行数据。
- 地图/天气/API 不可用时，要保留已保存内容，说明缺失能力并提供可行下一步；不得用模拟数据伪装成真实 Provider 结果。

## 2. 首发用户任务

1. 注册并验证邮箱，登录后看到自己的旅行列表。
2. 创建旅行：目的地、日期、预算（可选）和旅行节奏。
3. 收集地点：手工录入、搜索 POI、粘贴攻略或上传截图 OCR；识别文字可编辑，导入结果先作为候选，由用户确认后进入 Wishlist。当前不支持平台链接抓取或图片视觉分析。
4. 整理 Wishlist：查看地点、分类、地址、建议时长、优先级和备注；可增删改并重新规划。
5. 生成旅行计划：逐日查看时间线、交通/约束提醒、版本号；每次重生成保留旧版本。
6. 旅行中处理变化：记录天气变化（注明手动模拟或真实来源）、疲劳、地点取消、延误等事件；查看前后差异与原因后接受新版本。
7. 留下反馈并确认记忆建议；用户可以修改或删除记忆。
8. 使用 AI 旅行顾问探索目的地、挑选吃住玩地点、迭代行程草案；明确确认后才保存为旅行和计划。
9. 导出账户数据、退出或删除账户。

## 3. 前端信息架构与路由

| 路由 | 角色 | 主操作 | 关键状态 |
|---|---|---|---|
| `/login`、`/forgot-password`、`/verify-email`、`/reset-password` | 账户入口 | 登录、找回、验证、重置 | 提交中、失败、链接过期/已使用、成功 |
| `/trips` | 工作台首页 | 查看、创建旅行 | 首次空状态、加载、失败重试、旅行卡片 |
| `/trips/new` | 创建流程 | 输入目的地/日期/节奏/预算 | 字段校验、日期冲突、创建中、成功跳转 |
| `/trips/{tripId}` | 单次旅行主页 | 查看概览、收集地点、进入计划 | Wishlist 空/有内容、服务提示、加载/失败 |
| `/places?tripId=...` | 地点发现 | 搜索地点、确认加入收藏 | 未搜索、加载、无结果、失败、加入成功 |
| `/trips/{tripId}/import` | 内容收集 | 粘贴文本/截图 OCR、校对文字、审阅地点候选、确认 | OCR 无文字/失败、抽取中、候选为空、部分失败、待确认、已确认 |
| `/trips/{tripId}/plan` | 行程工作台 | 生成、查看版本和每日时间线 | 无收藏、规划中、无计划、警告、历史版本 |
| `/trips/{tripId}/events` | 行程调整 | 记录变化、运行重规划、审阅 Diff | 表单校验、处理中、无变化、变更/警告、失败 |
| `/trips/{tripId}/memory` | 旅行记忆 | 提交反馈、确认/编辑/删除记忆 | 无记忆、待确认、已确认、保存失败 |
| `/trips/{tripId}/sharing` | 旅行分享设置 | 管理好友对此 Trip 的只读授权 | 无好友、无授权、授权中、已撤销 |
| `/friends` | 好友圈入口 | 管理好友关系、接收申请、查看分享旅行 | 空好友、待处理申请、无分享、读取失败 |
| `/moments` | 旅行片段与照片动态 | 发布照片/感受、管理受众、浏览动态、生成文案草稿、确认记忆建议 | 默认私密、上传失败、AI 草稿/建议、授权撤销 |
| `/advisor`（可选 `tripId`） | AI 旅行顾问 | 探索目的地、推荐地点、迭代草案、确认保存 | 模型未配置、澄清中、候选、草案、警告、待确认、保存失败 |
| `/account` | 账户与隐私 | 导出、登出、删除账户 | 导出中/失败、删除二次确认、完成 |

全局导航在登录后保持一致：桌面固定侧栏列出我的旅行、创建旅行、地点探索、AI 旅行顾问、旅行概览、行程计划、现实事件、旅行记忆、地图与天气演示、账户与隐私。顾问入口可不绑定旅行来探索目的地，也可从单个 Trip 进入并携带 `tripId`。选中旅行后，旅行内部入口指向当前 Trip；尚未选择旅行时，相关入口仍显示并提示先选旅行。手机端使用两列导航，不将入口折叠进“更多”。登录/注册页不渲染已登录工作台导航。

## 4. 关键页面布局

### 旅行列表

- 顶部标题“我的旅行”，主按钮“创建旅行”。
- 卡片显示目的地、起止日期、旅行状态、收藏地点数及最近计划版本（无数据则省略）。
- 首次使用显示一个解释核心流程的空状态和唯一主 CTA；API 错误显示重试，不误显示为空列表。

### 旅行概览

- 标题区：目的地、日期、节奏、编辑旅行入口。
- 进度摘要：地点收藏数、计划版本、尚待确认的导入候选数。
- 主区：最近计划摘要和 Wishlist 列表；侧边区域提供“搜索地点”“导入攻略”“手动添加”“生成计划”。
- 当前地图为本地示意图：用收藏/计划顺序编号，不读取坐标、不表示真实道路；未来地图服务未配置时仍需保留列表管理能力。

### 计划页

- 顶部展示当前版本、生成时间、数据来源状态和“生成新版本”操作。
- 按天呈现可读时间线：开始/结束时间、地点、交通段（有数据时）、地点停留时长及约束提示。
- 版本历史可切换查看；生成新版本不覆盖旧版本。
- 当前天气为本地可切换样例：晴朗、多云、降雨、服务不可用；显示“本地模拟”且不触发行程重规划。真实服务接入后沿用 `未配置`、`加载中`、`可用（来源/更新时间）`、`已过期`、`不可用`状态，模拟事件仍需与真实预报区分。

### AI 旅行顾问

- 详细流程、对话/草案数据边界、服务端配置占位和分阶段验收见 [`agent-travel-advisor-design.md`](agent-travel-advisor-design.md)。
- 顾问可以先帮用户选目的地，也可以在指定 Trip 上做吃住玩推荐和迭代规划；关键条件显示为可编辑摘要。
- 生成结果先进入未确认草案。只有用户确认后才写入 Trip、Wishlist 和 Plan；历史计划不覆盖。
- 地点来源、路线和天气可信度清楚可见。没有路线几何时只能显示带“示意路线”标记的连线；Provider 不可用时仍保留列表和草案。
- 模型 API 凭据仅通过服务端环境配置。未配置时顾问显示不可用状态，不用静态内容冒充真实 Agent 响应。

### 重规划 Diff

- 先说明事件类型、生效时间和处理范围。
- 对每个地点展示保留、加入、移除、移动或更新，包含变更前后时间和原因；警告单独置顶。
- “采用新计划”与“返回旧版本/保留当前计划”需作为用户明确操作；若当前 API 已自动创建版本，页面仍应清楚说明新版本已保存，不得暗示尚未发生的确认动作。

## 5. 前端视觉与交互规则

- 产品气质：可靠、轻量、像旅行工作台；重点突出日期、地点和下一步操作，不使用营销落地页作为登录后的主界面。
- 桌面内容区建议最大宽度 1500px；旅行概览使用主内容 + 辅助栏，窄屏单列；页面标题、说明、主操作顺序固定。
- 以 CSS 自定义属性集中维护背景、卡片、正文、次要文字、边框、强调色、危险色、焦点环、圆角和间距。浅色为默认主题，深色可手动切换并保留用户选择；两种主题共用颜色语义变量。
- 表单具名标签、必要字段提示、输入错误就近显示；加载使用明确文案；操作成功用状态提示；失败保留用户已输入内容并提供可恢复操作。
- 破坏性动作（删除旅行/地点/账户）需明确对象和后果并二次确认；账户删除沿用不可撤销提醒。
- 键盘可完成导航和表单；焦点可见；状态不能只靠颜色表达；移动布局无横向溢出。
- 日期按旅行所在地/用户界面规则显示；时间默认展示旅行当地时间并标注时区策略，不能把 API UTC 时间直接当当地时间。

## 6. 前端配置边界

- `apps/web/lib/product-config.ts` 是前端产品常量入口：产品名、默认语言、默认时区、产品描述和 API 基址读取规则；页面不重复硬编码产品元信息。
- API 基址由 `NEXT_PUBLIC_API_URL` 控制。开发默认 `http://localhost:8000`；部署时通过环境配置设置，不将密钥写入 `NEXT_PUBLIC_*`。
- 地图 JS Key/安全密钥、天气 Key、模型 Key 均不属于前端配置；将来仅由 API/服务端读取。即使未来地图 SDK 使用公开浏览器 Key，也要单独限制域名与服务权限，并按 Provider 官方安全方案配置。
- 语言首发为简体中文（`zh-CN`），页面日期、错误信息和状态标签统一中文；不在本期增加多语言设置界面。
- Provider 展示使用统一前端状态模型：`not_configured | loading | available | stale | unavailable | simulated`，并携带 `source`、`updatedAt`、`message`；API 尚未返回字段时只显示 `not_configured`，不得推测可用。

## 7. 页面共用数据/交互状态

所有数据页面至少覆盖：初次加载、内容为空、内容可用、刷新中、部分内容不可用、请求失败和重试。搜索与保存操作需防止重复提交；切换 Trip 时不能闪现上一个 Trip 的数据。权限错误以通用“旅行不存在或无权访问”反馈，不泄漏其他账户资源存在性。用户输入只有在成功保存后才清空。

外部数据 UI 状态需呈现来源与时效：地点搜索的 Provider 故障不清空已有 Wishlist；地图服务故障不禁用手工录入；天气不可用不阻止查看既有计划，但需要天气保障的重规划条件必须由用户确认；模型抽取失败保留原文供手工处理。

## 8. 本期不做

- 不做公开分享链接、Trip 协作编辑、团队/组织权限或管理员后台。好友关系、单 Trip 只读授权、照片动态、评论/回应、AI 文案草稿和需确认的记忆建议基础版已实现；媒体使用本地存储，生产对象存储与运营安全仍待完成。
- 原生 iOS/Android、离线地图包、实时定位与自动行程追踪。
- 自动订票/支付、票务库存、商家交易、自动通知和紧急服务。
- 首发即承诺真实地图画布、实时天气或模型；这些接入按 Provider 设计文档另行验收。
- 自动接受 Agent/模型提出的地点或计划变更。

## 9. 设计验收

- 新用户可从注册/登录进入自己的旅行工作台，按“建 Trip → 加地点 → 生成计划 → 处理变化 → 管理记忆”的顺序完成核心流程。
- 任意页面的加载、空数据、服务不可用和失败状态都有解释和下一步，不以空白区域/无数据误导用户。
- 用户可以在没有地图画布、天气 Provider 和模型 Key 时完成 Trip、手工 Wishlist、计划与账户管理；外部能力未连接时明确标出边界。顾问演示数据必须明确标记为演示，不能写入正式旅行。
- 两个账户的导航、列表、错误和详情都只呈现各自数据；前端隐藏入口不能代替 API 所有权校验。
- 桌面和窄屏布局、键盘操作、表单错误、破坏性确认均达到可手工验收状态。
