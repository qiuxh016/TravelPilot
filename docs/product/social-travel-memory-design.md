# 好友圈与旅行记忆设计

状态：好友关系、Trip 只读分享、旅行动态/照片、评论/喜欢、AI 文案草稿和显式确认的 Trip 私有记忆建议已实现基础闭环。媒体支持本地目录与 S3 兼容存储；双账户脚本、存储配置校验和 S3 stub 验收已通过，SeaweedFS 开发容器可用于真实 S3 API 验收。生产供应商连通性、用户配额策略和运营安全仍待补充。

## 1. 产品目标

让旅行者在 TravelPilot 内记录并选择性分享旅行片段，也可整理文案后自行发布到外部社交媒体。好友可浏览获准分享的旅行、照片和感受。AI 可协助润色文案，并在用户单独授权后从文字中提出可确认的旅行记忆，供后续计划参考。

核心原则：

- 默认仅自己可见。创建好友关系不代表自动开放 Trip。
- 分享与 Trip 访问分别授权；每个 Trip 的访问权限由所有者明确授予，可撤销。
- 第一版好友只能查看获准 Trip 和分享内容，不共同编辑行程。
- 生成文案、发布内容、创建记忆、调整当前计划是四个独立动作，各自需要用户操作。
- 当前账号隔离必须保持有效；新增的好友读取权限只能通过显式授权路径检查。

## 2. 首版范围

### 包含

- 好友申请、接受、移除和屏蔽；仅通过明确邀请建立关系，不做通讯录抓取或公开用户发现。
- 对单个 Trip 授予好友只读权限，支持撤销；可单独控制 Trip 概览/计划是否可见。
- “旅行日记/好友圈”发布照片、文字感受，可关联 Trip、日期和地点；发布对象默认为“仅自己”，用户可选择“好友圈”。
- 好友动态流、评论与表情回应；好友可删除自己的评论，发布者可删除自己内容并管理评论。
- AI 生成可编辑的分享文案草稿；用户审阅并手动发布到 TravelPilot。
- 用户可复制文案或下载分享卡片，再自行发布到外部社交平台。首版不接入外部平台账号，也不自动发布。
- 从用户明确选中的分享文字生成旅行记忆候选；用户审阅、编辑并确认后，才写入私有 Memory。

### 不包含

- 公开互联网动态、公开个人主页、陌生人关注、群组、共同编辑、团队权限。
- 自动读取社交账号或自动同步外部帖子。
- 自动识别人脸、身份、生物特征或心理健康状态。
- 未经用户确认把模型推断写入记忆或自动改动正式计划。

## 3. 用户流程

1. 用户在旅行记忆页新建片段，选择照片、补充文字，可选关联 Trip/日期/地点。
2. 系统默认将受众设为“仅自己”。用户可明确改为“好友圈”；Trip 信息只有在拥有有效 Trip 分享授权时才可见。
3. 用户可单独点击“生成分享文案”。模型返回草稿，用户编辑后选择发布；生成失败不影响手动写作和保存。
4. 用户可在发布后手动复制文案/下载图片卡片，在其他社交媒体发布。
5. 用户若启用“从此内容提取旅行记忆”，系统只分析该次选择的文本，展示建议、原文依据和用途。
6. 用户确认后，建议写入自己的私有 Memory；拒绝或删除候选不会影响帖子。
7. 已确认的记忆可用于未来规划。若当前 Trip 尚未结束，用户另行点击“用此偏好调整当前计划”，系统先生成版本与差异预览，再由用户确认。

## 4. 访问控制与数据边界

### 权限关系

- 好友关系只允许在好友圈中展示内容，不自动授予任何 Trip 的读取权。
- `TripShareGrant` 为单个 Trip 的显式只读授权。授权内容范围由旅行所有者选择：仅旅行基本信息，或旅行基本信息及计划。
- Wishlist、导入原文、Agent/Tool trace、账户信息和私有 Memory 不随 Trip 共享。
- 好友可查看被授权 Trip 下明确设为好友可见的旅行片段；不能仅凭 Trip 授权看到该 Trip 所有私密片段。
- 分享帖子授权独立于 Trip 授权。未关联 Trip 的帖子也可分享给好友；关联 Trip 不自动公开 Trip 详情。
- 所有者可撤销 Trip 授权、将帖子改回私密、删除帖子或移除好友。撤销后新的 API 请求和媒体访问立即拒绝。

### 实现约束

- 保留现有 `require_request_scope` 的所有者校验用于写操作和私有资源。
- 增加独立的 `can_view_trip(user, trip)` 读取授权；不能通过放宽全局依赖来实现分享。
- 动态流、帖子详情、评论、反应和每一张媒体资源都必须在服务端检查当前用户、好友关系、帖子受众和有效分享授权。
- 撤销分享/好友关系后，已签发媒体 URL 可能在到期前仍可访问；应使用极短有效期签名 URL，或使用每次请求都鉴权的媒体代理，并在验收中验证撤销行为。
- 越权资源统一返回 404，不泄漏资源是否存在。

## 5. AI 文案与记忆建议

### 文案生成

- 用户通过明确按钮触发，输入只包括该用户选择的照片说明、文字和可选 Trip 摘要。
- 模型输出为草稿，页面标注“AI 建议”；用户可以编辑、重试或放弃。
- 不得因生成文案而自动发布或改变帖子受众。
- 未配置模型或调用失败时，仍可手工编辑和发布。

### 记忆提取

- 首版只分析用户选中的文本，不默认分析照片像素或表情。
- 目标是旅行相关偏好与体验，例如“喜欢慢节奏”“对街头小吃印象很好”；不做情绪诊断或长期心理画像。
- 每条候选应显示所依据的原文片段、建议内容、置信提示和“将用于后续旅行规划”的说明。
- 候选存入独立的 `MemorySuggestion`，不能直接写入现有 `Memory`；用户确认后才转换为私有 Memory，并保留来源帖子与确认时间。
- 好友分享内容不代表授权模型处理。作者必须单独启用记忆提取；评论者内容不得被帖子作者拿来创建对方记忆。
- AI 推断不能改变其他好友的资料、偏好或行程。

## 6. 图片与隐私

- 图片原文件存对象存储；数据库只保存所有者、对象键、类型、大小、校验和、缩略图状态等元数据。当前支持本地开发目录和 S3 兼容私有存储；生产强制使用 S3 后端。
- 上传限制文件类型、大小和单用户存储额度；校验真实文件格式，生成缩略图并进行恶意文件扫描。
- 默认移除 EXIF/GPS 元数据；如保留位置，必须由用户逐次明确选择，并在分享前提示可能暴露的精确位置。
- 原图与缩略图均通过每次请求鉴权的 API 按动态受众访问，不使用公开 URL；本地开发落盘于 `.data/media`。生产可配置 S3/MinIO 兼容私有桶，仍保留相同 ACL 检查。
- 帖子删除时撤销媒体访问并删除原图和衍生图；账号删除按既定级联规则清理帖子、评论、候选记忆和媒体。
- 日志不得记录图片内容、完整帖子文本、访问令牌或模型密钥。需在上线前确定备份中的删除时限和数据保留策略。

## 7. 建议数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `Friendship` | requester、recipient、status、created_at、updated_at | 申请、接受、屏蔽；唯一用户对约束 |
| `TripShareGrant` | trip_id、owner_user_id、grantee_user_id、scope、revoked_at | 单 Trip 只读授权，可撤销；只允许好友获得 |
| `TravelMoment` | owner_user_id、trip_id、day、place_id、body、audience、created_at | 分享/日记内容，默认 PRIVATE |
| `MediaAsset` | owner_user_id、moment_id、object_key、mime、size、checksum、exif_stripped、status | 图片元数据及处理状态 |
| `MomentComment` | moment_id、author_user_id、body、created_at | 仅具备帖子可见权限者可评论 |
| `MomentReaction` | moment_id、user_id、kind | 每用户每帖子至多一个当前反应 |
| `MemorySuggestion` | owner_user_id、source_moment_id、candidate、evidence、status、confirmed_memory_id | 用户确认前与私有 Memory 分离 |

状态枚举建议：好友 `PENDING/ACCEPTED/BLOCKED`；帖子受众 `PRIVATE/FRIENDS`；分享范围 `TRIP_SUMMARY/TRIP_AND_PLAN`；记忆候选 `PENDING/CONFIRMED/REJECTED/DELETED`。

## 8. 页面入口与状态

- 全局导航增加“好友圈”，内部提供“动态”“好友”“分享设置”。
- `/moments/new` 创建旅行片段；Trip 记忆页增加“写旅行日记/分享”入口。
- `/moments/{momentId}` 帖子详情、受众、评论、AI 文案和记忆建议操作。
- Trip 页面增加“分享设置”，显示受邀好友、授权范围、授予时间和撤销操作。
- `/account/privacy` 汇总 AI 处理授权、媒体位置设置、数据导出/删除入口。
- 每个界面需覆盖私密/好友可见、无好友、待处理申请、空动态、上传中/失败、AI 未配置/失败、无权访问、授权撤销和删除状态。

## 9. 验收标准

- 用户 A 的私有 Trip、私有帖子和照片对 B 不可见；成为好友本身不改变该结果。
- A 授予 B 只读 Trip 权限后，B 只能读取指定范围与明确分享的内容；B 不能修改计划、Wishlist 或设置。
- A 撤销授权、删除好友或将帖子转私密后，B 的后续 API 与媒体请求立即被拒绝。
- 生成文案不会发布帖子；发布帖子不会自动生成记忆；记忆建议只有 A 确认后进入 A 的私有 Memory。
- 评论和反应不能被未获准用户创建或读取；用户只能删除自己评论，帖子作者可按策略管理该帖评论。
- 删除帖子或账户后，其媒体原图、衍生图及可访问链接按已定义清理策略失效。
- 模型不可用时，手写日记、照片管理和手动发布仍可工作。
- 上传拒绝伪装格式、超限文件；默认清除 EXIF/GPS；日志不含敏感正文和密钥。

## 10. 实施顺序

1. 冻结分享授权规则、媒体存储/保留期限、好友屏蔽策略和数据导出格式。
2. 实现好友关系与只读 Trip 授权；先完成跨账户 API 越权测试，再提供前端入口。
3. **基础版已实现**：本地媒体存储、图片重编码、EXIF 清理、鉴权读取、删除、动态受众、好友动态流、评论和喜欢。
4. **基础版已实现**：服务端模型文案草稿、复制/手动发布，以及基于用户选中文字的记忆候选、来源证据和确认/拒绝。
5. **对象存储适配已实现，真实供应商验收待完成**：可从本地媒体目录切换为 S3 兼容私有存储；补备份清理、监控、病毒扫描策略和账户级存储额度。
6. 为跨账户媒体撤销、好友移除和记忆授权补全自动化安全验收与生产发布门槛。
7. 将已确认记忆用于未来规划；另行实现当前计划的 Diff 预览与确认，不允许隐式重排。当前版本只把记忆加入 Trip，未自动重排正在进行的计划。

当前基础版已完成不代表生产部署条件已满足。部署到多实例环境前，需要配置并验收受控对象存储，补充备份保留/删除时限、病毒扫描和监控策略，并执行完整部署环境验收。分享与记忆仍遵循用户显式授权、按请求鉴权和数据隔离规则。
